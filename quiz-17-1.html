For finding the minimum of \(n = 1024\) numbers, what is the critical path length (span) of SERIAL_MIN compared to RECURSIVE_MIN?
  • (A) Serial: \(1024\), Recursive: \(512\)
  • (B) Serial: \(1023\), Recursive: \(10\)
  • (C) Serial: \(10\), Recursive: \(1023\)
  • (D) Both have span equal to \(1024\).
Answer: (B) Serial: 1023, Recursive: 10
• Why (B) is True: SERIAL_MIN must execute \(n - 1 = 1023\) sequential loop comparisons one after another. In contrast, RECURSIVE_MIN constructs a balanced binary tree where pairs are evaluated concurrently across time stages. The critical path length (span) is \(L = \lceil \log_2 n \rceil = \log_2(1024) = 10\) steps.
• Why others are false: (A) misses the logarithmic depth of tree reductions; (C) inverts the two algorithms; (D) ignores the concurrency enabled by recursive tree decomposition.
2
In \(2 \times 2\) block matrix multiplication \(C = A \cdot B\), why does intermediate data decomposition (\(D_{k,i,j} = A_{i,k} B_{k,j}\)) achieve 8-way concurrency while standard output data decomposition achieves only 4-way concurrency?
  • (A) It computes twice as many multiplications simultaneously in Stage I before pairwise summation.
  • (B) It uses Strassen's matrix formula.
  • (C) It eliminates all additions.
  • (D) It converts the dense matrices into sparse matrices.
Answer: (A) Decoupled Multiplications in Stage I
• Why (A) is True: Output data decomposition defines 4 tasks corresponding to the 4 output blocks \(C_{i,j}\). Intermediate data decomposition decouples each \(C_{i,j}\) into two outer products \(D_{1,i,j} = A_{i,1}B_{1,j}\) and \(D_{2,i,j} = A_{i,2}B_{2,j}\), yielding \(2 \times 4 = 8\) concurrent multiplications in Stage I, followed by a reduction stage (Stage II) of 4 additions.
• Why others are false: Strassen uses 7 multiplications for \(2 \times 2\); additions are not eliminated (they form Stage II); the computation is dense linear algebra.
3
Which statement correctly captures the fundamental distinction between speculative and exploratory decomposition according to Grama et al.?
  • (A) Speculative has unknown output; Exploratory has unknown input.
  • (B) In speculative decomposition, the input at a branch is unknown; in exploratory decomposition, the output of tasks originating at a branch is unknown.
  • (C) Speculative decomposition never requires checkpointing or rollback.
  • (D) Exploratory decomposition applies only to dense linear algebra.
Answer: (B) Input Unknown vs. Output Unknown
• Why (B) is True: According to Grama et al. (Sections 3.2.4 & 3.2.5), in speculative decomposition, tasks are dispatched before a switch/condition evaluates, meaning the input state of downstream tasks is unknown. In exploratory decomposition (e.g., 15-puzzle search), the input state is known, but the output (whether a search path reaches a valid goal solution) is unknown until explored.
• Why others are false: (A) reverses the definitions; (C) speculative execution frequently mispredicts, requiring state rollback; (D) exploratory decomposition applies to discrete search and optimization problems.

Why is pure recursive decomposition inefficient for parallel Quicksort on 64 processors?
  • (A) Pivot selection is mathematically impossible on multicores.
  • (B) The root partition requires serial time \(\Theta(n)\) on 1 core, leaving 63 cores completely idle at the start.
  • (C) Quicksort has an exponential span.
  • (D) Recursive algorithms cannot execute concurrently.
Answer: (B) Root Amdahl's Law Serialization
• Why (B) is True: In pure recursive decomposition, a single core partitions the full array around the pivot in sequential time \(\Theta(n)\). On 64 cores, 63 cores sit 100% idle during this phase (Amdahl's serialization bottleneck). Hybrid decomposition overcomes this by parallelizing the root partition across all cores before switching to recursive sorting.
• Why others are false: Pivot selection is straightforward; parallel Quicksort with hybrid partitioning has span \(O(\log^2 n)\), not exponential; recursive task trees are standard parallel patterns.
