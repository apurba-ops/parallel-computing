Review Quiz 18-1
1
In the Cilk/TBB work stealing scheduler, why does a worker thread push and pop tasks from the BOTTOM of its deque (LIFO stack order), while idle thieves steal from the TOP (FIFO queue order)?
  • (A) Bottom access preserves temporal cache locality for the worker, while top stealing yields the largest-granularity subtrees for the thief.
  • (B) The C++ language specification strictly prohibits FIFO queueing in multithreaded runtimes.
  • (C) Double-ended queues cannot physically be accessed from both ends concurrently without deadlocking the kernel.
  • (D) Thieves only steal trivial single-instruction base cases to avoid network congestion.
Answer: (A) Cache Locality + Coarse-Grained Stealing
• Why (A) is True: The worker operates on the bottom of its deque in LIFO order (like a function call stack), so data from recently spawned subtasks is already warm in L1/L2 caches. Conversely, the thief steals from the TOP (the oldest ancestor task in the recursion tree), ensuring that the stolen task represents a massive subproblem near the root that keeps the thief busy for a long time without needing further steals. Furthermore, operating at opposite ends of the deque minimizes lock contention between owner and thief!
• Why others are false: Concurrent lock-free deques (e.g., Chase-Lev deque) are standard in parallel computing; stealing tiny leaf tasks causes catastrophic scheduler thrashing.
2
In randomized work stealing, what is remarkable about the total communication overhead bound \(O(p \cdot L)\) proven by Blumofe and Leiserson?
  • (A) It scales exponentially with total computational work \(W\).
  • (B) It is completely independent of total computational work \(W\), depending strictly on processor count \(p\) and critical path length (span) \(L\).
  • (C) It requires zero inter-process network messages on all clusters.
  • (D) It only holds when the system is restricted to a single processor (\(p = 1\)).
Answer: (B) Communication Overhead Decoupled from Work \(W\)
• Why (B) is True: In work stealing, busy processors never send coordination messages; communication occurs strictly during steal attempts by starving idle processors. Blumofe and Leiserson mathematically proved that the expected number of steals is at most \(O(p \cdot L)\). As a result, doubling or tripling problem work \(W\) does not increase network communication overhead at all, provided the critical path length \(L\) remains constant!
• Why others are false: Communication is non-zero; it scales linearly with \(p\) and span \(L\), completely independent of total work \(W\).
3
Why does Guided Self-Scheduling (GSS) dispatch large task chunks at the beginning of execution and progressively smaller chunks towards the end?
  • (A) To burn through work rapidly initially with minimal scheduling contention, while fine-tuning tail load balance near the end without idle stragglers.
  • (B) Because processors run significantly slower during the first few seconds of program execution.
  • (C) It completely avoids using shared memory or thread synchronization locks.
  • (D) GSS always dispatches chunks of fixed size 1 under all circumstances.
Answer: (A) Low Contention + Tail Load Balancing
• Why (A) is True: At the start, large chunk sizes (\(K_t = \lceil R_t / p \rceil\)) minimize the frequency of master queue requests, avoiding bottleneck contention. Near the end, chunk sizes smoothly decay down to single tasks, ensuring that all processors finish nearly simultaneously without leaving one processor stuck on a massive remaining chunk while all other cores sit idle (straggler elimination).
• Why others are false: Hardware clock frequency does not change dynamically due to chunk size; fixed size 1 is standard naive self-scheduling, which incurs high synchronization overhead.
4
Why does over-subscribing multiple software processes/threads to a single physical processor often improve overall application throughput?
  • (A) It overclocks the physical silicon execution units beyond thermal design power.
  • (B) The operating system can immediately switch to an active ready thread when another thread is stalled waiting for high-latency DRAM or network packets (Latency Hiding).
  • (C) It bypasses hardware cache hierarchies and page tables entirely.
  • (D) It doubles the number of physical arithmetic logic units (ALUs) on the die.
Answer: (B) Dynamic Latency Hiding
• Why (B) is True: Main memory accesses to DRAM require 200+ CPU clock cycles; network round-trips require thousands of cycles. When a thread stalls on memory or communication, the hardware/OS scheduler context-switches to an alternate ready thread on the same physical core, keeping arithmetic execution units saturated (Latency Hiding).
• Why others are false: Over-subscribing software threads does not alter silicon clock speed, ALU counts, or bypass hardware caches.
